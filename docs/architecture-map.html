What this repo is, structurally

  • Mostly a browser app: pages fetch Proxmox data with React Query from the client side.
  • Authentication model: login returns a Proxmox ticket, stored locally in the browser, then reused and refreshed.
  • Important exception: console access needs server-side help for termproxy and websocket upgrade handling.
  • Deployment shape: simple Docker container on port 8080, commonly placed behind Cloudflare.
  • Main risk area: auth/cookie/CORS/websocket interplay rather than complex backend business logic.

Pages & navigation

src/routes/* src/components/app-sidebar.tsx src/router.tsx

The application is route-driven. The authenticated shell protects most pages and redirects anonymous users to /login.

  • Login: collects Proxmox base URL, user, realm and password, with optional 2FA.
  • Dashboard: cluster summary from listNodes and listAllGuests.
  • Guests / Nodes: details, actions, monitoring, console and backups.
  • Create: QEMU and LXC creation flows assembled from Proxmox form payloads.
Fast reading: if you want to understand this codebase quickly, start with src/lib/proxmox/client.ts, then the authenticated routes, then the console proxy pieces.
